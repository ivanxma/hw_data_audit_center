Native Streaming keeps ordinary events in one message and fragments oversized events. The service limit remains 1 MiB. Runtime JSON streaming.max_event_bytes sets the logical reassembly limit (default 16 MiB; range 1–64 MiB); streaming.max_pending_fragment_bytes bounds durable incomplete events (default 128 MiB). Use Control Center → More actions → Apply stream settings to apply saved limits and pacing with the selected workload images. The writer is replaced first. Limit decreases require a separate drain and review.
Request controls under streaming: put_max_records (default 500), put_requests_per_second (4), put_bytes_per_second (850000), get_max_records (1000), get_idle_max_ms (2000) and get_bytes_per_second (1500000). Small events share API requests while remaining separate messages. Idle polling backs off automatically. Byte pacing takes priority over the request ceiling; bounded retries handle residual throttling.
