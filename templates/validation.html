Recommended source configuration

Apply through a custom HeatWave DB configuration with the appropriate database administrator.

log_bin = ON
binlog_format = ROW
binlog_row_image = FULL
binlog_row_value_options = ''
binlog_expire_logs_seconds = 604800
gtid_mode = ON
enforce_gtid_consistency = ON

Retention: the application requires more than 259,200 seconds (3 days) and recommends 604,800 seconds (7 days). Allow for the longest connector outage, snapshot duration and recovery window; monitor binlog storage growth.

Complete images: FULL records all available row columns, including large values. Disable PARTIAL_JSON so JSON updates include complete documents. Inserts have an AFTER image; deletes have a BEFORE image; updates have both. Initial snapshots record the current row with a SNAPSHOT operation.

Existing sessions: global session-variable changes affect new source connections. Reconnect application writers after changes to row image or format, then verify a controlled update before production capture. Changes cannot reconstruct images from older incomplete binlogs.

Snapshot privileges: HeatWave supports FLUSH_TABLES with LOCK TABLES in place of the broader RELOAD privilege. The app accepts either flush privilege and still requires the other connector grants.

HeatWave: use supported configuration parameters; some changes require a DB restart. GTID mode is required for this deployment. Debezium gets a unique replication server ID, a persistent offset topic and a separate schema-history topic.

References: Debezium MySQL connector · MySQL binlog settings
